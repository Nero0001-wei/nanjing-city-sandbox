# 南京 · 山水之间

React + Three.js 南京主城城市沙盘。地理布局来自已校正的 v2 地图，美术方向来自已确认的卡通等轴风格图。本项目为本地可运行的第一版，不依赖在线地图 Key，也没有登录或后端服务。

## 运行

```sh
npm install
npm run dev -- --port 5173
```

访问 http://127.0.0.1:5173/ 。`npm run build` 生成可部署的 `dist/`，`npm run preview` 预览构建结果。

## Three.js r187（2026-11-02）

依赖从 `0.186.1` 升级并固定为 `0.187.0`，`package.json` 与锁文件同步。升级命令为 `npm install --save-exact three@0.187.0`。升级后停止旧开发服务，使用 `npm run dev -- --port 5173 --force` 重建依赖缓存，并刷新已打开的预览页，避免热更新时混用新旧着色器。

首次升级时，`src/tree-material.js` 的 `onBeforeCompile` 适配 r187 的 `diffuseBRDF`，保留原有外观；该阶段使用 `MeshStandardMaterial`，未启用 EON。后续的柔光版本已切换为下节所述的原生 EON 材质。继续使用 WebGL 与 PCF 阴影，地形不投影但接收阴影。

验证：79 项测试及生产构建通过，新增测试直接验证安装版本的真实着色器片段。Chrome 在 Apple M5 / ANGLE Metal 上实际运行 r187，14 个地标 GLB 与树库均加载成功，浏览器错误为 0；全景、树木近景、两座桥及手机视口截图保存在 `artifacts/three-r187/after/`，升级前对照在 `before/`。2,059 棵树、622,530 个实例三角面、14 个批次保持不变，树冠与完整景点底座重叠数为 0。模型、地图数据、地标摆放与全局光照配置的哈希均未改变，模型面数和文件大小不变。完整记录见 `artifacts/three-r187/`。

## 柔和日光与树木材质（r187）

`src/sky-environment.js` 在本地生成线性 HDR 天空，通过 r187 的 PMREM 立方体预过滤建立环境光；冷色天空、宽阔暖色亮区和较暗的地面半球提供不同方向的反射。只在场景初始化时生成，销毁场景时释放，不请求外部 HDR 文件，也不增加逐帧环境捕获。`src/render-style.js` 将原先较强的黄色半球光改为少量补光，调整主光角度及强度，保留 Neutral 色调映射。2048 阴影图继续使用 PCF，采样半径从 1.5 调至 2.6、阴影强度 0.9，静态阴影缓存规则不变。

树木和连续地形使用 `MeshPhysicalMaterial`，`diffuseRoughness` 分别为 0.65、0.55，启用 [r187 原生 EON 粗糙漫反射](https://github.com/mrdoob/three.js/pull/34379)。树木保留顶点色和自定义法线，降低表面凹凸幅度、增加两档逐渐淡出的叶簇色差、区分树皮与树冠粗糙度。直接光和间接光的 BRDF 全部由 Three.js 原生计算，不再叠加旧的余弦包裹柔光，避免 EON 在叶簇轮廓处产生异常亮点。没有使用自发光、透明叶片或额外树木绘制批次。

验证记录在 `artifacts/soft-light-r187/`：80 项测试与生产构建通过；真实 Apple M5 / ANGLE Metal 上确认 PMREM 立方体环境图和两套 EON 着色程序生效，控制台与着色器错误为 0。检查全景、丘陵及正反向树木近景、完整景点底座、两座桥、手机尺寸；2,059 棵树与 14 处完整景点/桥梁底座的投影重叠为 0。树库依然是 4,116 面、89,320 字节，单棵 198/390 面；所有 GLB、地图数据、摆放参数的哈希不变。未进行目标手机帧率测试。

## 模型与数据

`blender/nanjing-landmarks.blend` 是可编辑的地标资产库，各模型位于独立 Collection，并以网格排开展示。

`public/models/*.glb` 是单独导出的网页模型，`manifest.json` 记录各自尺寸。模型由本项目脚本原创生成，是简化风格模型，不是测绘复原模型。

重新生成模型：

```sh
/Applications/Blender.app/Contents/MacOS/Blender --background --factory-startup --python blender/build_landmarks.py
```

Blender 源文件采用 Z-up、正面 -Y；GLB 导出为 Y-up、正面 +Z。模型原点在地面中心，桥墩允许向下延伸。库中的排版偏移在导出 GLB 后才应用，不会进入网页模型。

`public/data/nanjing.json` 保留 `../output/layout-v2/nanjing-layout-data.json` 的地标锚点、水体及地形范围。道路以原有 784 段主干道为起点，从同一批 OSM 原始缓存选择必要连接，裁切、修复和简化后显示 935 个连续路段，其中 99 段为匝道。采用共享节点和真实道路路径，不按邻近距离编造连接。当前画幅为核心主城与滨江地标，未覆盖南京全市行政区。

更新校正地图后运行 `npm run prepare:data`，再运行 `npm test` 检查坐标与资产。

场景使用局部源像素映射：

```
X = (source_x - 350) × 0.6
Z = (source_y - 430) × 0.6
北 = -Z
```

地标根节点保持原始锚点。模型尺寸与示意山体高度独立于真实地图比例；不能将模型尺寸当成实际建筑占地或高度。原始 JSON 的旧 scene_position 没有直接使用，避免将另一套比例混入场景。

## 文件分工

- `src/main.jsx`：React 界面、列表、状态与显示控制。
- `src/scene.js`：Three.js 场景、地形、道路、水体、GLB、选中与相机交互。
- `src/geo.js`：统一投影、几何裁切和空间判断。
- `src/road-network.js`：沿 OSM 共享节点计算连续坡道与隧道入口，市区高架统一为一层示意高度。
- `src/roads.js`：白色简化桥面、转角与路口接缝、稀疏桥墩及连续隧道走向线。
- `src/road-clearance.js`：为放大的中华门、夫子庙模型计算局部显示避让；识别短跨河桥，保留原始坐标与共享节点。
- `src/terrain-profile.js`：示意山脊、景点平整预留地、岸线与道路距离查询、植被分布。
- `src/terrain-surface.js`：平滑地形网格、岸边浅水带、草地色块与细微凹凸、岩石、水面细纹。
- `src/render-style.js`：明亮自然的配色、Neutral 色调映射、柔光与 PCF 阴影、地表微纹理。
- `src/sky-environment.js`：本地 HDR 天空、r187 PMREM 环境光及资源释放。
- `src/tree-material.js`：原生 EON 树木材质、叶簇色差和随像素覆盖淡出的细节。
- `src/vegetation.js`：七类树形、叶团接触暗部、按区域混合的实例化植被及树冠避让。
- `src/buildings.js`：按真实占地多边形拉伸白模，保留内院，分块合并绘制。
- `src/building-footprints.js`：建筑占地距离和空间索引，使植被避让建筑。
- `src/city-walls.js`：连续转角墙身、垛口、真实开洞的简化城门，以及建筑和植被共用的墙体避让索引。
- `scripts/extract-city-walls.py`：从缓存提取现存墙体、城门位置与门洞，排除历史示意线和重复轮廓。
- `blender/build_landmarks.py`：13 个模型的生成与导出。
- `scripts/prepare-data.mjs`：从校正布局更新浏览器数据，保留地理锚点。
- `scripts/extract-roads.py`：从原始地图缓存建图，选取必要连接，修复断头、删除悬空支线与末端回环，保留交叉口后简化曲线并验证连通性。
- `tests/layout.test.js`：锚点不偏移、道路与隧道语义、裁切、GLB 完整性检查。
- `scripts/check-browser.cjs`：本机 Chrome 的独立浏览器交互与截图检查；其中 Playwright 路径需按其他电脑的环境调整。

## 精度边界

这是一套可运行的风格化初版。山体是示意高度场；市区立交统一为地面加一层高架，不再逐层复刻 OSM 的 `layer`。长江大桥、南京眼保留与地标模型匹配的桥面高度。坡道高程和桥墩是示意值，不是测量数据。长江及岛屿沿用二维方案的概括轮廓。城市基础地面为整块沙盘底座。地标体量与细节可继续在 Blender 中打磨。

地形丰富版：钟山使用连续多峰山脊和缓坡，阅江楼下补充狮子山的简化起伏；山体边界渐变融入地面。湖岸和江岸沿原轮廓增加浅水带与砂石色岸缘，不更改水体位置。加入草地色差、少量坡面岩石、滨水灌木、成簇阔叶树和山地针叶树。水面细纹遵循减少动态效果的系统偏好。这些高度和植被分布是美术设计，未引入 DEM 测绘高程或真实林地调查数据。

地形丰富版未修改 `blender/` 或 `public/models/` 的模型资产。地标根节点的平面坐标不变，高度随脚下地形更新；钟山地标周围保留平整预留地，供后续手工 Blender 模型替换。植被避免道路、水体及景点预留范围。

地形版验证：7 项数据、资产及地形检查通过；已检查钟山近景、关闭树木后的山体连续性、玄武湖岸线，以及原有桌面和手机交互。模型文件的 SHA-256 与修改前一致。地形对比与近景截图在 `artifacts/terrain/`。

生成风格图仅用于色彩、材质和模型复杂度参考，不用于回推位置。正式布局以数据为准。

## 建筑白模数据

真实轮廓层使用先前获取的 OpenStreetMap 原始 API 地图快照（2026-10-29），与道路采用相同 WGS84 坐标和投影。这一层没有通过截图推测、随机摆放或移动建筑。`data/building-footprints.json` 保存 22,083 个提取出的完整轮廓及来源；保留复杂多边形与内院，不重复绘制 `building:part` 和父建筑。新增的艺术化建筑组团独立存放，见下方“街区背景”。

`public/data/buildings.json` 当前显示 10,000 个筛选轮廓，由上一版的 2,400 个增加而来。最小面积降至约 120 平方米，取消距主干道约 292 米的限制，将街区内部纳入覆盖；按空间网格均衡选择，保持原始占地和朝向。景点预留地、艺术化山体、水体、加宽道路和城墙两侧均有避让。候选数据并非完整城市覆盖，没画出的地块不代表现实中没有建筑。每个轮廓都记录了 OSM 对象 ID、原始轮廓、相关标签和来源 URL。

当前高度来源：

| 来源 | 轮廓数 | 处理 |
| --- | ---: | --- |
| OSM `height` 标注 | 2,055 | 按标注的米数；这是社区地图数据，未独立测量 |
| 楼层估算 | 613 | 住宅每层 3 米，其他每层 3.6 米 |
| 类型估算 | 7,332 | 按类型使用保守默认高度，未知类型 12 米 |

平面轮廓不放大、不平移。高度在统一地图比例下额外放大 1.6 倍，以适配微缩沙盘；因此不是测量级 3D 实景。估算状态保存在 `height_source`，原始或估算米数保存在 `height_m`，网页页脚与操作指引也有说明。全部为无窗、无贴图的浅色体块，不替代后续 Blender 地标。

重新生成：

```sh
npm run prepare:buildings
```

这会先由 `scripts/extract-buildings.py` 提取原始缓存中的建筑，再由 `scripts/prepare-buildings.mjs` 筛选显示集合。编辑选择上限、道路范围或估算规则后，运行该命令并执行 `npm test`。本次无需地图 API Key。建筑数据同样遵循 ODbL 1.0。

## 参考图的渲染调整

保留现有地理布局、连通路网和白模道路，单独调整颜色、光照、材质及树木。草地改为更鲜明的黄绿色与深浅绿层次，水面改为清蓝色，岸缘过渡更浅；保留克制的细水纹，并为草地加入微小凹凸。Neutral 色调映射保留颜色，暖色日光配合冷色补光、VSM 模糊阴影与地面接触暗部，降低硬阴影感；背景使用暖白色。

1,550 棵树的位置沿用原有避让规则，树形扩充为樟树、悬铃木、银杏、垂柳、松树、雪松及花树，共 21 个实例批次。树冠由不规则叶团组成，叶团相接处加入轻微烘焙暗部；尺寸、冠形与颜色有变化。山地偏松柏、滨水增加柳树，花树少量点缀。这是美术混合，不是实际树种调查。树冠半径按道路和建筑预留范围约束，避免挡住道路。

静态阴影只在模型加载或显示开关改变时重算，旋转和平移复用阴影；树木保持实例化批量绘制。Blender / GLB 地标文件、道路数据与路网连通规则均未修改。本轮已检查桌面、手机视口、山地和湖岸近景，以及树木和模型开关；树种分布与冠幅避让报告在 `artifacts/render-look/validation.json`，渲染对比在 `artifacts/render-look/`。

## 街区背景

`public/data/urban.json` 当前包含 946 个铺地区块、600 栋概括白模、574 块庭院绿地、90 块公园绿地和 571 个规划种植点。街区范围参考已有 OSM 建筑覆盖，地块边界使用缓存中的主次干道与住宅街道；完整闭合的用地轮廓提供住宅、商业、校园和公园提示。大地块再做艺术化分割，浅米灰铺地与绿化间隔形成城市背景。地块间的缝隙是铺地边界，不加入导航路网。

概括建筑采用平行住宅楼、庭院低层楼和办公体块三种简化组合，朝向跟随地块，保持无窗白模。它们使用 `source: procedural_infill` 和 `height_source: artistic_massing`，尺寸和高度为美术概括，不是新增的实测建筑数据。扩充真实白模和明城墙后已重新生成：概括白模由 868 栋减至 600 栋，优先为真实轮廓让位，并避让水体、山地、主路、城墙及景点预留区。
